# CYDLE 1.0 delivery roadmap — Godot

`CYDLE_MASTER_SPEC.md` is the normative source for game design and release requirements. `docs/godot/` records the current engine, architecture, visual direction, and asset production rules. This roadmap records what actually exists; a plan or catalog entry is not working gameplay.

## Development strategy (2026-11-12)

The active strategy is **FULL GAME FIRST**: connect every major Master Spec system into a campaign that can be completed, then deepen edge cases, balance, and presentation. The entries below report implementation status; they are not a queue of isolated feature slices. A checkpoint commit is a safety measure, so continue to the next missing campaign-critical system while the session permits. Defer saved Simulation Lab presets, report exports, cosmetic polish, secondary settings, and redundant tests until functional campaign coverage exists.

## FULL GAME FIRST implementation order

This is a breadth-first integration directive, not a sequence of narrow acceptance gates. Keep the native game playable while wiring the missing major systems together. Do not spend time on saved Simulation Lab presets, report exports, or visual polish until campaign completion, the other core systems, persistence, and offline/autopilot exist end to end.

1. Complete the 12-sector campaign loop through sector 12 and depth-13+ endgame, including all six biome rules, boss milestones, finale, and persistent recovery.
2. Complete all 24 events, six quest chains, contracts, faction reputation, requirements, outcomes, and one-time rewards across route generation, UI, and META/RUN saves; current integrations are partial.
3. Bring combat/content interactions to catalog coverage: all enemies, elites, bosses, skills, statuses, drones, equipment triggers, telegraphs, and bounded chains must run through the same deterministic 100 ms simulator.
4. Finish the connected economy and progression loop: all item operations, character/tree/implant/drone progression, garage, rewards, cargo ownership, defeat, tow, extraction, and sector unlocks.
5. Implement configurable autopilot and offline simulation (maximum 12 hours) using real route, node, combat, choice, and reward transactions in the shared engine, with explicit stop reasons and exactly-once recovery.
6. Finish the required interface coverage for garage, operator, inventory, road, battle, quests, reports, autopilot, Build Lab, Simulation Lab, settings, and save recovery.
7. Verify a seeded new game through all sectors, finale, endgame, save/load, and Windows export. Only after functional coverage, prioritize regression cleanup, balance, art/audio, accessibility, and polish.

Commits are recovery checkpoints, not completion gates. Each checkpoint should keep this list and `HANDOFF.md` aligned with actual code and verification evidence.

## Commit gates

- Commit coherent safety checkpoints regularly, but do not treat a feature commit as a reason to stop or wait for another instruction.
- Every ported calculation has a checked reference fixture before downstream consumers are connected.
- Run relevant checks after gameplay integration changes; run full import, headless tests, and Windows export at release gates.
- Preserve the reference code and baseline; do not mark a subsystem complete based on file presence.
- Do not claim 1.0 until the master-spec release checklist is verified on a real native build.
